# 章の品質チェックリスト

第1章（パイロット章）を書いて決めた基準。各章はこのリストで点検してから公開する。

## 数学的な正確さ
- [ ] 定義は「何を満たせば〇〇と呼ぶか」が一意に読める（「〜のようなもの」で終わらない）
- [ ] 定理には仮定をすべて書いている（「任意の」「ある」を省略していない）
- [ ] 証明は各ステップの根拠（定義・前の定理・仮定）を示している
- [ ] 反例が本当に反例になっているか、具体的な値で確かめた
- [ ] 記号の流儀（ℕ に 0 を含めない、⊆ を使う、補集合は Aᶜ）がサイト全体と一致している

## 段階性（数学A の知識だけで読めるか）
- [ ] 前提章（prereq）以外の知識を使っていない。使う場合は「第◯章で扱う」と明記した
- [ ] 新しい記号は、初めて出るときに読み方と意味を書いた
- [ ] 定義の前に、直観（イメージ・身近な例）を置いた
- [ ] 抽象的な定義の直後に、具体例と「当てはまらない例」を置いた
- [ ] 「よくある誤解」を最低1つ取り上げた

## 証明の書き方
- [ ] 証明は <Proof> で折りたたみ、「まず自分で考える」余地を残した
- [ ] 証明の型（例：要素を1つ取る、両方向の包含、背理法）を本文で名前を付けて説明した

## 演習・確認問題
- [ ] 確認問題（<Quiz>）は 3〜6 問。誤答の選択肢は「よくある誤解」に対応させた
- [ ] すべての選択肢について、なぜ正しい／誤りかを解説で触れた
- [ ] 演習問題は基本・標準・発展の3段階。発展にはヒントを付けた
- [ ] 解答は「答え」だけでなく、考え方の流れを書いた
- [ ] Quiz の id は `<章slug>-qNN` 形式で、章内で一意

## 図・インタラクティブ部品
- [ ] 図や部品は、本文の説明を置き換えるのではなく補う役割にした
- [ ] 有限の図で無限を示す場合は「直観であって証明ではない」と明記した

## 表示
- [ ] スマホ幅で、表や数式が画面からはみ出さない（はみ出す場合は横スクロール）
- [ ] npm run build で KaTeX エラーが出ない
